## Decisions log (with why)

- **2026-07-09 (M2)** — Pipeline event-ownership for a no-tools milestone, resolved by direct doc citation (docs/03 §7.1's "Emitted by" column + §8's sequence diagram), not inference: `Agent.handle()` emits LISTENING/TRANSCRIBING as `skipped` only when `user_input.source == "typed"` (voice, M4, will already have emitted the real ones before `handle()` is called — the guard prevents double-emission); SELECTING_TOOL/EXECUTING/OBSERVING are all emitted `skipped` together whenever `Router` returns `DirectAnswer` (the loop itself just `break`s without touching this code — the skip-emit exists purely to satisfy the UI-completeness rule that every stage gets *some* event every request); REMEMBERING is emitted `started`→`skipped` by `Agent` itself (no MemoryService until M5, and docs/03 §7.1 lists Agent as a valid emitter for it); **SPEAKING is not emitted at all** in M2 (no carve-out for a no-voice path exists in the docs the way Listening/Transcribing has one — inventing one would assert ownership Agent doesn't have; stays in the neutral "pending" chip state until M4).
- **2026-07-09 (M2)** — `AgentCancelled` (in `agent/agent.py`) is a plain `Exception`, deliberately **not** a `NovaError` subtype. Why: `NovaError`s become conversational replies (A-6) — a cancellation is the opposite, the user explicitly doesn't want a reply. Keeps `Agent.handle()`'s `-> AssistantReply` signature honest on every *completing* path while letting `AgentWorker` distinguish cancelled/replied/broke via three separate signals. Inferred, not doc-stated.
- **2026-07-09 (M2)** — `EventStatus` has no `CANCELLED` value; a cancelled stage is represented as `FAILED` with `payload={"reason": "cancelled"}` instead of a mid-milestone enum addition (a P-3 contract change for a corner case). Revisit if the UI ever needs to render cancellation distinctly from failure.
- **2026-07-09 (M2)** — `AgentWorker` is a `QObject` moved to a `QThread` via `.moveToThread()`, not a `QThread` subclass — matches the only other cross-thread precedent in the codebase (`core.events.EventBus`), keeping one cross-thread idiom in the app (TD-3) instead of two. `AgentWorker.cancel_current()` must be invoked as a **direct** call (or an explicit `Qt.ConnectionType.DirectConnection`), never a plain queued connection — a queued connection would sit undelivered in the worker thread's own event queue until its current blocking `handle_request()` call returns, defeating cancellation entirely. `app.py` wires `MainWindow.cancel_requested` to it with `Qt.ConnectionType.DirectConnection` explicitly for this reason.
- **2026-07-09 (M2)** — Safety blocking has two distinct cases, not spelled out together anywhere in the docs: a *hard* block (`SafetyBlocked` raised, no candidate generated at all) vs a *soft* per-candidate filter (`LLMResponse(finish_reason="safety")`, a response did come back). `ProviderManager.generate()` catches `SafetyBlocked` before its generic retry/fallback handling and re-raises untouched — no retry, no cooldown mark. `Agent.handle()` treats both cases identically: short-circuit straight to a gentle-refusal reply, bypassing `Router` entirely. Now reflected in docs/06 §6's error matrix and docs/10 §2.1.
- **2026-07-09 (M2)** — With the tool registry permanently empty in M2, every `RepairRoute` the `Router` produces is structurally a defensive path (a provider hallucinating a tool call despite an empty `tools` list) rather than a real invalid-argument repair. There's no way to reach docs/06 §6's "repair also fails, no ERROR" outcome differently from "iteration cap hit" until M3's tools make them independently reachable — so M2 collapses both onto the iteration-cap mechanism. Revisit once M3 lands.
- **2026-07-09 (M2)** — import-linter (`import-linter==2.6`, verified) needs **5 contracts, not 3**, to express M2's layering: a single `layers` contract can't express "`ui` restricted to core-only, `agent` allowed core+providers" because layers grant every entry transitive access to everything below it as a block — any grouping that lets `agent` reach `providers` also lets `ui` reach it. Solution: two disjoint `layers` contracts (one that deliberately omits `ui` so it can't inherit `providers` access) + two `forbidden` contracts (`ui → agent/providers`, and the reverse `agent/providers → ui` — a gap an earlier draft of this plan missed by trusting a paraphrase instead of re-deriving the tool's actual semantics) + the pre-existing `agent → concrete adapters` forbidden contract. All 5 are in `pyproject.toml`.

Swapping in real icons later is a one-line change in `nova/ui/views/settings_view.py::_KeyRow`, not a design constraint; follow the same Lucide-sourcing pattern already used for `alert-triangle`/`shield-question` (see Gotchas below).

## Gotchas discovered

- `QAbstractButton.click()` (incl. `QPushButton`) is a no-op — does not emit `clicked` — when the button is disabled. Useful for testing a disabled-during-request Send button "for real" without needing `qtbot.mouseClick`; but if a test wants to isolate a *different* guard (e.g. an internal `_awaiting_reply` flag) independent of Qt's own disabled-widget suppression, re-enable the widget first so the click actually reaches the handler.
- pytest-qt 4.5.0's `waitSignal` context manager throws (`AttributeError: 'MultiSignalBlocker' object has no attribute 'check_params_callback'`) if the watched signal fires more than once inside the `with` block — use `qtbot.wait_until(predicate)` instead for signals that may emit rapidly/repeatedly (e.g. EventBus bursts from a worker thread).
- `QWidget.isVisible()` reflects the *whole ancestor chain*, not just the widget's own flag — a widget tree that's never been `.show()`n reports `isVisible() == False` even right after `setVisible(True)`. Cost time in a PulseRing repaint-count test and a StageChip expand/collapse test; fix is `.show()` (+ `qapp.processEvents()`) before asserting visibility/paint counts, or use `.grab()` which forces a synchronous render regardless of shown state.
- `Qt.WidgetAttribute.WA_TransparentForMouseEvents`, applied recursively to a composite row's children, reliably forwards clicks to one outer handler — used so `StageChip`'s whole row (icon/text/status labels) click-through to the outer widget's single `mousePressEvent`. Confirmed via a real `qtbot.mouseClick` dispatch, not just a direct method-call test.
- Variable fonts (`Inter[opsz,wght].ttf`, `JetBrainsMono[wght].ttf` from the google/fonts repo) load fine via `QFontDatabase.addApplicationFont`, and `QFont.setWeight()` correctly selects the right instance — no need to source separate static per-weight files.
- Lucide renamed `alert-triangle` → `triangle-alert` and `shield-question` → `shield-question-mark` upstream at some point (old names 404 on raw.githubusercontent.com). Fetched under the new names; saved locally as `assets/icons/alert-triangle.svg` / `shield-question.svg` to match the names docs/05 §5 actually specifies.
- Qt's SVG renderer does not resolve Lucide's `stroke="currentColor"` — icons are tinted by rendering to a transparent QPixmap then filling with `CompositionMode_SourceIn` (`nova.ui.theme.load_icon`), not by editing the SVG source.
