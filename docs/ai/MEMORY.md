- **2026-07-11 (M5)** — `tests/perf/` is a new top-level test directory (docs/13 §8's NFR-1/2/4 automated verification, previously unimplemented): `test_memory_leak.py` compares heap growth in the second half of 50 fake requests against the first half rather than asserting an absolute byte budget — a real leak trend compounds, steady per-request allocation doesn't, and an absolute-byte assertion would be allocator/GC-noise-flaky across machines/CI runners in a way a growth-*ratio* comparison isn't. `test_latency.py` needed one fix mid-session: its own sanity assertion (`total_elapsed >= simulated_delay`) flaked once in the full-suite run (`0.296 >= 0.3`) — `time.sleep()` isn't a strict lower bound under scheduler jitter; loosened to a 10% tolerance rather than dropping the check, since it's what proves the test isn't vacuously passing.
- **2026-07-11 (M5)** — `QTimer.singleShot()` called before a `QApplication` instance exists is accepted silently and simply **never fires** — no exception, no warning. Hit while writing a one-off offscreen verification driver that scheduled a driver-callback timer at module import time (before `nova.app.main()` had constructed `QApplication`); fixed by monkeypatching `MainWindow.show()` (called by `main()` right before `app.exec()`, i.e. after `QApplication` definitely exists) to schedule the timer from inside. Not a product bug — scratchpad-only script — but worth a Gotchas entry since it'll bite the same way in any future ad-hoc offscreen driver.
- **2026-07-10 (M4)** — Primary TTS swapped `edge-tts` → `pocket-tts` (Kyutai Labs) **per explicit owner direction mid-build**, not an agent-initiated substitution. Why: a local, CPU-only neural voice removes edge-tts's unofficial-Microsoft-endpoint fragility (docs/04 TD-6's own ⚠️) entirely rather than mitigating it, and needs no network per-utterance. Real, accepted cost: `pocket-tts` pulls in PyTorch 2.5+ — pinned to the CPU-only wheel index (`download.pytorch.org/whl/cpu` via `[tool.uv.sources]`) to avoid the much larger CUDA-bundled default; measured real footprint on this dev machine: `torch` ≈ 477 MB alone, whole dev venv ≈ 1.53 GB (up from docs/04's original ≈ 300–400 MB estimate for the whole app). `TD-7`'s original rejection of `silero-vad` ("avoid pulling in torch/ONNX for VAD") is now a moot premise since torch is in the tree anyway for TTS — documented as a cross-reference note in TD-7, VAD left unchanged (still nothing to gain from switching). Two more real findings from hands-on testing (not assumptions): (1) `TTSModel.load_model()` took 30–100s even with cached weights on this machine — `SpeechService.warm_up_tts()` was added specifically so this cost lands at app startup (background thread) rather than on a user's first spoken reply; (2) voice selection must use pocket-tts's built-in catalog names (`cosette`, `alba`, …) — an `hf://` voice-cloning URL (the obvious-looking API for "pick a voice") 404s/requires gated Hugging Face access, confirmed by an actual failed call during testing, not by reading docs alone. Docs amended: docs/04 TD-6 (rewritten) + TD-7 (cross-ref note) + dependency budget, docs/08 §4 (behavior + contract additions), docs/11 §4 (additive `end_listening()`/`warm_up_tts()`/`tts_mode_changed`), docs/14 §5 (disk estimate). All footprint numbers are flagged ⚠️ pending the real M6 PyInstaller artifact, not asserted as final.
- **2026-07-10 (M4)** — `SpeechService.listen()` needed a second "end" verb beyond the frozen contract's `cancel_listening()`: Esc must **unconditionally discard** (no STT call, regardless of how much was said), while re-pressing the mic must **stop-and-transcribe** whatever's buffered — one boolean flag can't honestly serve both outcomes, since they're opposite results from the same "stop the loop now" trigger. Added `end_listening()` as an explicit second flag (`_end_requested`) checked alongside `_cancel_requested` at the same loop boundary; both flags (and the 30s hard cap, and real VAD `SPEECH_ENDED`) are evaluated together each frame, matching the existing `Agent._raise_if_cancelled()` polled-flag idiom generalized from one condition to several.
- **2026-07-10 (M4)** — `TTSEngine.abort()` exists as a **second**, non-cooperative interruption mechanism alongside the `should_stop` callback every `speak()` implementation already polls. Why: FR-13's <100ms bound is delivered by `AudioPlayback.abort()` (PortAudio's `Pa_AbortStream`, safe cross-thread, discards buffered audio immediately) — `should_stop` polling alone can't hit that bound, since MP3-era chunk/frame arrival could be hundreds of ms apart and a polled flag only takes effect *between* chunks. `abort()` defaults to a no-op on the ABC (pyttsx3 has no `sounddevice` stream of its own to abort — SAPI5 owns its own COM-based audio output outside our control — so its interruption really is best-effort via `should_stop` only, documented as such rather than oversold).
- **2026-07-09 (M2)** — Pipeline event-ownership for a no-tools milestone, resolved by direct doc citation (docs/03 §7.1's "Emitted by" column + §8's sequence diagram), not inference: `Agent.handle()` emits LISTENING/TRANSCRIBING as `skipped` only when `user_input.source == "typed"` (voice, M4, will already have emitted the real ones before `handle()` is called — the guard prevents double-emission); SELECTING_TOOL/EXECUTING/OBSERVING are all emitted `skipped` together whenever `Router` returns `DirectAnswer` (the loop itself just `break`s without touching this code — the skip-emit exists purely to satisfy the UI-completeness rule that every stage gets *some* event every request); REMEMBERING is emitted `started`→`skipped` by `Agent` itself (no MemoryService until M5, and docs/03 §7.1 lists Agent as a valid emitter for it); **SPEAKING is not emitted at all** in M2 (no carve-out for a no-voice path exists in the docs the way Listening/Transcribing has one — inventing one would assert ownership Agent doesn't have; stays in the neutral "pending" chip state until M4).
- **2026-07-09 (M2)** — `AgentCancelled` (in `agent/agent.py`) is a plain `Exception`, deliberately **not** a `NovaError` subtype. Why: `NovaError`s become conversational replies (A-6) — a cancellation is the opposite, the user explicitly doesn't want a reply. Keeps `Agent.handle()`'s `-> AssistantReply` signature honest on every *completing* path while letting `AgentWorker` distinguish cancelled/replied/broke via three separate signals. Inferred, not doc-stated.
- **2026-07-09 (M2)** — `EventStatus` has no `CANCELLED` value; a cancelled stage is represented as `FAILED` with `payload={"reason": "cancelled"}` instead of a mid-milestone enum addition (a P-3 contract change for a corner case). Revisit if the UI ever needs to render cancellation distinctly from failure.
- **2026-07-09 (M2)** — `AgentWorker` is a `QObject` moved to a `QThread` via `.moveToThread()`, not a `QThread` subclass — matches the only other cross-thread precedent in the codebase (`core.events.EventBus`), keeping one cross-thread idiom in the app (TD-3) instead of two. `AgentWorker.cancel_current()` must be invoked as a **direct** call (or an explicit `Qt.ConnectionType.DirectConnection`), never a plain queued connection — a queued connection would sit undelivered in the worker thread's own event queue until its current blocking `handle_request()` call returns, defeating cancellation entirely. `app.py` wires `MainWindow.cancel_requested` to it with `Qt.ConnectionType.DirectConnection` explicitly for this reason.
- **2026-07-09 (M2)** — Safety blocking has two distinct cases, not spelled out together anywhere in the docs: a *hard* block (`SafetyBlocked` raised, no candidate generated at all) vs a *soft* per-candidate filter (`LLMResponse(finish_reason="safety")`, a response did come back). `ProviderManager.generate()` catches `SafetyBlocked` before its generic retry/fallback handling and re-raises untouched — no retry, no cooldown mark. `Agent.handle()` treats both cases identically: short-circuit straight to a gentle-refusal reply, bypassing `Router` entirely. Now reflected in docs/06 §6's error matrix and docs/10 §2.1.

## Gotchas discovered

- **M6**: `nova.ui.theme` does not export `button_style()` function — attempting to call it raises `AttributeError`. Buttons use the global QSS stylesheet instead; use `setStyleSheet()` only for per-widget overrides (color text, background, etc.), not for structural styling.
- `QAbstractButton.click()` (incl. `QPushButton`) is a no-op — does not emit `clicked` — when the button is disabled. Useful for testing a disabled-during-request Send button "for real" without needing `qtbot.mouseClick`; but if a test wants to isolate a *different* guard (e.g. an internal `_awaiting_reply` flag) independent of Qt's own disabled-widget suppression, re-enable the widget first so the click actually reaches the handler.
- pytest-qt 4.5.0's `waitSignal` context manager throws (`AttributeError: 'MultiSignalBlocker' object has no attribute 'check_params_callback'`) if the watched signal fires more than once inside the `with` block — use `qtbot.wait_until(predicate)` instead for signals that may emit rapidly/repeatedly (e.g. EventBus bursts from a worker thread).
- `QWidget.isVisible()` reflects the *whole ancestor chain*, not just the widget's own flag — a widget tree that's never been `.show()`n reports `isVisible() == False` even right after `setVisible(True)`. Cost time in a PulseRing repaint-count test and a StageChip expand/collapse test; fix is `.show()` (+ `qapp.processEvents()`) before asserting visibility/paint counts, or use `.grab()` which forces a synchronous render regardless of shown state.
- `Qt.WidgetAttribute.WA_TransparentForMouseEvents`, applied recursively to a composite row's children, reliably forwards clicks to one outer handler — used so `StageChip`'s whole row (icon/text/status labels) click-through to the outer widget's single `mousePressEvent`. Confirmed via a real `qtbot.mouseClick` dispatch, not just a direct method-call test.
- Variable fonts (`Inter[opsz,wght].ttf`, `JetBrainsMono[wght].ttf` from the google/fonts repo) load fine via `QFontDatabase.addApplicationFont`, and `QFont.setWeight()` correctly selects the right instance — no need to source separate static per-weight files.
- Lucide renamed `alert-triangle` → `triangle-alert` and `shield-question` → `shield-question-mark` upstream at some point (old names 404 on raw.githubusercontent.com). Fetched under the new names; saved locally as `assets/icons/alert-triangle.svg` / `shield-question.svg` to match the names docs/05 §5 actually specifies.
- Qt's SVG renderer does not resolve Lucide's `stroke="currentColor"` — icons are tinted by rendering to a transparent QPixmap then filling with `CompositionMode_SourceIn` (`nova.ui.theme.load_icon`), not by editing the SVG source.
- `QTimer.singleShot()` called before a `QApplication` exists silently never fires (no error) — see M5 decisions log entry above. Only schedule driver/test timers after the app is constructed (e.g. from inside a patched `show()`, or after `QApplication(sys.argv)` in a script).
- Newly-inserted child widgets in an already-shown `QVBoxLayout` don't paint on the very next `.grab()` — Qt defers the actual layout pass to the next event-loop iteration (a posted `LayoutRequest`), so a synchronous `set_facts([...]); widget.grab()` with no event-loop turn in between grabs a still-zero-sized child. Call `QApplication.instance().processEvents()` between the mutation and the `.grab()` in any offscreen driver/test that adds widgets and immediately screenshots.
